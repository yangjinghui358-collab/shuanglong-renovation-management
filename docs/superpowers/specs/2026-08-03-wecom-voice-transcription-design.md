# 企业微信语音转写入库设计

## 目标

在现有 `wecom-chat-pipeline` 中增加企业微信语音处理能力：从会话存档下载语音，调用阿里云智能语音交互（ISI）一句话识别生成文字，把转写结果保存到阿里云 PostgreSQL，并让现有装修事件、待办和简报分析使用转写文字。

## 约束与选择

- 继续使用企业微信 Finance SDK 作为消息和媒体数据源。
- 转写服务选用阿里云智能语音交互（ISI）“一句话识别”，优先使用新用户免费试用。
- 不在 2 核、1.6 GB 内存的生产服务器上常驻运行 Whisper 模型。
- 转写超出免费额度时不自动转付费；任务保留为可重试状态。
- 密钥只写入 `/etc/wecom-chat-pipeline/secrets.env`，权限保持 `0600`。
- 既有文本消息、事件分析和简报行为不变。

## 架构

### 1. Finance SDK 媒体下载

扩展 C++ 命令行工具，增加 `media <sdkfileid> <output-file>` 动作。命令通过 `GetMediaData` 按 `outindexbuf` 循环下载分片，直到 `is_finish=1`，再原子化写入目标文件。中途失败删除临时文件，不留下假的完整媒体。

### 2. 消息标准化

`wecom-archive-adapter.mjs` 对语音消息保留：

- `sdk_file_id`
- `voice_size`
- `play_length`
- 原始解密消息中媒体处理所需的字段

普通文本消息的输出结构保持兼容。日志不输出 `sdkfileid`、密钥或语音内容。

### 3. PostgreSQL 存储

扩展现有 `media` 表，保存：

- 企业微信媒体标识
- 本地路径、文件类型、字节数和 SHA-256
- 转写文字
- 转写服务商
- `pending` / `downloading` / `transcribing` / `done` / `retryable` / `failed` 状态
- 尝试次数、最近错误和完成时间

`msg_id + media_type` 继续作为唯一键，保证重新抓取和服务重启时幂等。成功转写后，`media.transcript` 保留纯文字，`messages.content` 更新为 `【语音转写】<文字>`，使既有分析链路无需改变查询方式。

### 4. 阿里云 ISI 语音识别

新增独立转写客户端，使用阿里云 ISI 一句话识别 RESTful API。客户端使用 Node.js 内置 `crypto` 完成 POP 签名，不引入额外阿里云 SDK。客户端先使用 AccessKey 换取短期访问 Token，缓存 Token 到到期前，再上传服务器上的音频数据。不为语音创建公网下载 URL，不引入 OSS 依赖。

服务器每次只处理 1 条语音。转写成功、文字和 SHA-256 写入数据库后立即删除本地音频；仅转写失败时临时保留，便于有上限重试。

默认使用普通话/中英文混合引擎，保留配置阿里云 AppKey 和地域端点的能力。语音超过 60 秒或格式不受支持时记为 `retryable`，本期不自动切换到异步长录音服务。

### 5. 任务编排和重试

主采集流程插入新消息后，为语音消息 upsert `media` 任务。每轮处理有限数量的待转写记录，避免占满 CPU 或 API 并发。

可重试错误使用有上限的延迟重试；鉴权失败、额度用尽等配置错误不高频重试。一条语音失败不阻塞其他文本消息入库。

### 6. 历史语音回填

新增一次性回填命令，从现有语音消息最小 `seq` 之前重新调用会话存档。消息表依靠 `msg_id` 去重，但会为已有语音补齐媒体标识并创建转写任务。

如企业微信已超出历史媒体的可下载期限，该记录标记失败并保留，不伪造转写结果。

## 错误处理

- SDK 下载失败：保留任务和错误码，删除不完整文件。
- ASR 限额或暂时错误：保留本地音频，降低重试频率。
- ASR 结果为空：不更新 `messages.content`，标记需人工检查。
- 数据库写入失败：不删除已下载媒体，下一轮可幂等重试。
- 主流程日志只输出消息 ID 的短摘要和状态，不输出音频或转写正文。

## 测试策略

- C++ 媒体下载通过小型命令集成测试或可控 SDK 边界验证分片追加、完成判断和临时文件清理。
- Node.js 单元测试覆盖语音标准化、阿里云 Token 获取与缓存、ISI 请求、转写成功、空结果、限额和重试。
- PostgreSQL 存储测试覆盖媒体幂等 upsert 与 `messages.content` 更新。
- 回归测试要求现有 6 个测试继续通过。
- 部署验收使用一条真实历史语音，核对 `media.transcript`、`messages.content`、状态和日志。

## 部署和回滚

1. 备份 PostgreSQL 业务库和 `/opt/wecom-chat-pipeline`。
2. 构建新 Finance CLI，保留旧二进制文件。
3. 执行兼容性数据库迁移。
4. 写入阿里云 ISI 凭据、AppKey 和功能开关。
5. 运行自动测试和一次手动回填。
6. 重启 systemd 服务，检查日志、进程、数据表和真实转写结果。

回滚时恢复应用目录和 Finance CLI 备份，重启旧服务。新增数据库字段保留但不被旧代码使用，避免破坏性回滚。

## 验收标准

- 新语音消息可自动下载并转写。
- 转写文字同时出现在 `media.transcript` 和对应 `messages.content`。
- 现有事件/待办/简报分析能读取语音转写文字。
- 历史 5 条语音在媒体仍可获取的前提下完成回填。
- 重复抓取、重复启动和失败重试不产生重复数据。
- 未配置 ASR 凭据时，文本消息采集仍然正常。
- 部署后服务保持 `active (running)`，日志不含凭据和转写正文。

## 部署前必需外部条件

需要在阿里云开通智能语音交互 ISI，创建仅具有语音识别调用权限的 RAM 用户，并创建一句话识别项目。向服务器提供：

- `ALIYUN_ACCESS_KEY_ID`
- `ALIYUN_ACCESS_KEY_SECRET`
- `ALIYUN_NLS_APP_KEY`
- `ALIYUN_NLS_REGION`（默认 `cn-shanghai`，必须与 ISI 项目所在地域一致）

凭据未提供前可完成代码、测试、数据库迁移和媒体下载验证，但无法完成真实语音转写的最终验收。
