# PostgreSQL 备份与恢复演练手册

本手册定义验收流程，不包含生产凭据或可直接覆盖生产的命令。恢复只能在网络隔离、明确标记的测试实例执行，严禁以生产主机或生产数据库名为目标。

## 备份策略基线

- 连续归档 WAL，支持时间点恢复（PITR）。
- 每日完整备份；保留周期与异地/跨故障域副本数由业务负责人和 DBA 书面批准。
- 备份加密，加密密钥与备份分离保管；备份存储账号不与应用账号共用。
- 保存不可变或防误删副本；保留策略变更和删除需二人复核。
- 监控最后成功时间、持续时长、大小异常、WAL 归档延迟和校验失败。

## 演练前

1. 录入变更单：源备份 ID、目标时间点、隔离目标、预期 RPO/RTO、执行/复核人。
2. 验证目标为非生产账号、非生产网络和非生产数据库名，无生产 DNS 或通知出站能力。
3. 在未解密业务内容的前提下校验备份 manifest/校验和、所需 WAL 连续性和加密密钥可用性。
4. 禁用 AI、企业微信、短信、邮件和 OSS 生产出站凭证，防止恢复环境误发通知或写入生产文件。

## 演练执行

1. 记录开始时间，将指定完整备份恢复到隔离实例。
2. 应用 WAL 到批准的目标时间点；保留恢复日志，但证据中删除连接字符串和客户内容。
3. 启动数据库后先保持应用断开，验证 PostgreSQL 版本、时间线、恢复终点和只读核查账号。
4. 使用脱敏聚合检查：各业务表行数、主/外键约束、孤儿引用、迁移版本、导入批次和审计链连续性。
5. 用测试密钥连接应用，验证登录、首页读取、项目证据关联、归档可恢复性，不触发真实通知。
6. 记录可用恢复完成时间，计算实测 RTO 和相对于目标时点的 RPO。

## 验收与收尾

- [ ] 备份校验和、WAL 连续性和恢复终点正确。
- [ ] 表行数/约束/引用/迁移版本检查通过，原始聊天未丢失。
- [ ] 已确认数据、待确认数据与审计历史保持语义，未产生新的正式财务记录。
- [ ] OSS 对象引用以只读 HEAD/元数据方式抽样核对，不将客户文件复制到演练证据。
- [ ] 实测 RPO/RTO 满足批准目标；不满足时建立整改项并不得勾选生产就绪。
- [ ] 销毁隔离恢复环境前经二人复核目标，按批准的敏感数据处置流程执行。

每季度及 PostgreSQL/备份工具升级、存储策略变更、大型迁移后重新演练。
