# Phase 1C 生产就绪清单

适用域名：`https://admin.shuanglongzhuangshi.cn`。本清单仅用于上线前准备与验收；本任务未部署服务、未修改 DNS、未修改数据库、未上传 OSS。

所有项目必须在独立测试环境先通过，再安排经审批的生产变更窗口。每项记录执行人、复核人、时间、结果和不含隐私数据的证据链接。

## 1. 发布前决策

- [ ] Phase 1A 本地预览已由老板书面验收，Phase 1B/1C 范围已批准。
- [ ] 确认单门店上线边界，同时验证数据结构与权限支持多门店隔离。
- [ ] 定义可量化 RPO/RTO、维护窗口、回滚触发条件和业务责任人；“尽量不丢数据”不作为可验收指标。
- [ ] 客户会话存档告知、合同隐私条款、数据用途/权限/留存期已经负责人审核。
- [ ] 历史聊天暴露过的服务器密码已轮换，生产登录改用 SSH 密钥。

## 2. 服务器与网络

- [ ] 完成[server inventory 模板](../data/server-inventory.md)，不记录密码、token、客户数据或聊天原文。
- [ ] 操作系统和容器/运行时版本在支持期内，时区为 `Asia/Shanghai`，NTP 同步正常。
- [ ] 公网安全组仅开放 80/443 以及经批准的 SSH 来源；PostgreSQL 5432、API 上游端口和内部任务端口不对公网。
- [ ] PostgreSQL 仅监听本机/私网必要地址，现有企业微信采集服务保持独立且不被替换。
- [ ] 运行用户无交互 shell、无 sudo，只能读取必要配置和写入必要目录。
- [ ] 日志、临时文件、上传缓存和构建产物设置容量/轮转/保留上限，磁盘阈值有报警。

## 3. Nginx 与 HTTPS

- [ ] DNS 变更方案、TTL、回滚值和负责人已审批；只在发布窗口执行。
- [ ] 基于 [`infra/nginx/admin.shuanglongzhuangshi.cn.conf.example`](../../infra/nginx/admin.shuanglongzhuangshi.cn.conf.example) 生成环境配置，用 `nginx -t` 检查后再 reload。
- [ ] 80 仅用于 ACME 校验和跳转 HTTPS；证书链完整，私钥权限最小，TLS 1.0/1.1 禁用。
- [ ] 证书自动续期在测试环境验证，到期前 30/14/7 天报警。
- [ ] HSTS 只在 HTTPS 和子域全部就绪后启用；CSP 根据前端实际资源列表收紧并回归测试。
- [ ] `/api/health` 超时短且不返回密钥或内部错误栈；上传大小、请求超时和限速符合业务实际。
- [ ] 访问日志脱敏，不记录 Authorization、Cookie、签名 OSS URL 或完整查询参数。

## 4. 应用与密钥

- [ ] Web、业务 API、AI 任务、同步任务和通知任务责任边界清晰，每个进程都有自动重启和健康检查。
- [ ] 数据库密码、OSS 凭证、AI 密钥和通知密钥仅存在服务器环境/批准的密钥管理系统，文件权限最小。
- [ ] 敏感角色开启二次验证；高风险审批、权限修改和永久删除要求再次验证。
- [ ] 真实、演示、AI 推测、待确认、已确认、已驳回、已归档状态在 API 与 UI 均可区分，演示数据不进入真实统计。
- [ ] 财务、报价、设计变更和增减项未经老板确认不得成为正式数据。
- [ ] 完整聊天查看、金额/权限修改和删除记录完整审计，日志不存聊天原文副本。

## 5. OSS 与文件

- [ ] 使用独立私有 bucket，禁止公共读/写；服务端 RAM 角色只能访问指定 bucket/prefix。
- [ ] 客户端不持有长期 AccessKey；上传/下载使用短效签名 URL，日志不记录完整签名 URL。
- [ ] 设计图、报价单、票据和已确认重要媒体使用不可猜测的对象键、服务端加密、版本/防误删策略。
- [ ] 默认不下载全部群媒体；只存档经 AI 推荐且由项目经理/老板确认的重要媒体。
- [ ] 上传校验 MIME、扩展名、大小、哈希和业务归属；扫描或隔离策略通过测试。
- [ ] OSS 失败任务可幂等重试，最终失败可见且报警，数据库不存大文件本体。
- [ ] 生命周期、售后留存、法务保留和客户删除/归档流程已批准。

## 6. PostgreSQL、备份与恢复

- [ ] 现有 `wecom_chat` 采集库保持只读消费；新建经营数据库使用独立角色和最小权限。
- [ ] 生产迁移在独立测试环境执行并通过前向/回滚演练，上线前记录模式版本。
- [ ] 持续归档 WAL，每日完整备份，备份加密且与主机故障域分离，成功/失败/超时均有监控。
- [ ] 备份账号与运行账号分离，删除/缩短保留期需要高风险审批。
- [ ] 按[备份与恢复演练手册](backup-restore.md)完成真实备份的隔离恢复，验证时间点、行数/约束/附件引用与应用启动。
- [ ] 恢复演练测得的 RPO/RTO 满足批准指标，演练证据不包含客户隐私。

## 7. 健康检查与可观测性

- [ ] 存活检查仅证明进程可响应；就绪检查分别报告业务库、只读源、OSS 和必要任务依赖。
- [ ] `/api/health` 只返回 `ok/degraded`、依赖状态和脱敏的最后同步时间，不回传主机、账号、SQL 或错误栈。
- [ ] 监控覆盖 HTTP 5xx/延迟、进程重启、数据库连接池、同步新鲜度、AI 失败、OSS 重试、通知未送达、备份年龄和磁盘。
- [ ] 07:00 简报以 `Asia/Shanghai` 运行，即时重大风险与通知重试通过测试。
- [ ] 报警有接收人、升级路径、抑制规则和处置手册；敏感信息只发老板私聊。

## 8. 发布、回滚与验收

- [ ] 发布包可追溯到已审核提交，构建过程不包含 `.env`、日志、数据库 dump 或媒体。
- [ ] 发布前备份成功且可恢复，迁移与应用回滚步骤已在测试环境实演。
- [ ] 按[集成与验收测试矩阵](../data/integration-acceptance-matrix.md)执行所有 P0/P1 案例，缺陷具有责任人和处理决定。
- [ ] 服务器重启后 Nginx、Web/API、AI/同步/通知任务自动恢复，无丢失原始聊天、重复导入或未确认正式财务数据。
- [ ] 发布后检查域名/HTTPS、登录/MFA、权限、首页真实数据、演示标识、证据展开、通知和审计日志。
- [ ] 达到回滚触发条件时立即停止发布；不在故障现场即兴修改生产数据或权限。
